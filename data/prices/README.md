# Price data

Highwater uses this data to estimate the cost of model calls whose harness did not record one, and to give an API-equivalent cost for calls covered by a subscription. How each call's cost is worked out is in [data semantics](../../docs/data-semantics.md#cost-assessment).

Highwater embeds only `prices.json` and never downloads prices while running.

## Why costs are assessed

The cost a harness records is often missing or misleading on its own:

- **OpenCode with a ChatGPT login records $0**, because OpenCode removes the price for that login ("the subscription covers usage"), although models.dev lists those models at API prices.
- **GitHub Copilot changed billing on 1 June 2026.** Before then it charged per request and models.dev listed its models at $0; from then it charges credits at each model's API rates.
- **Pi records an API-equivalent cost for subscriptions without saying so**, because it prices its `openai-codex` (ChatGPT plan) provider at OpenAI's API rates.
- **Claude Code records no cost per call**, and a recorded $0 cannot be told apart from a free call using the call record alone.

So each call is classified by its billing mode first (`billing-modes.toml`), then given a recorded, free, estimated, API-equivalent or unknown cost. Billed and API-equivalent totals are never added together. The table keeps every models.dev provider, because OpenCode can record any of them, which makes it about 2.9 MB uncompressed (330 KB with gzip). Prices are updated by hand. Time-of-day pricing is not modelled; no supported harness's sessions use a provider that has it.

## Files

| File | Maintained | Contents |
| --- | --- | --- |
| `prices.json` | Generated by `scripts/update-prices.py build` | Every models.dev provider's price history with amendments applied, plus the billing modes. |
| `amendments/imported-model-prices.toml` | Generated by `scripts/update-prices.py import-amendments` | Corrections converted from [wakamex/model-prices](https://github.com/wakamex/model-prices). |
| `amendments/manual.toml` | By hand | Highwater's own corrections. They take precedence over imported ones. |
| `billing-modes.toml` | By hand | Which harness providers bill per token and which are covered by a subscription, and when. |
| `LICENSE.models.dev`, `LICENSE.model-prices` | Copied | The MIT licences of the two sources. |

## Sources

- **[models.dev](https://github.com/sst/models.dev)** (MIT, copyright 2025 models.dev) is the base price list. `build` replays the git history of every `providers/*/models/*.toml` file on its main branch. Each price starts at the time its commit reached main, which usually lags the provider's real change by days.
- **[wakamex/model-prices](https://github.com/wakamex/model-prices)** (MIT, copyright 2026 wakamex) records cited corrections where models.dev was late or wrong, and prices read from providers' pricing pages. `import-amendments` converts its `data/corrections.toml`, `data/research_corrections.toml` and `data/observed.json`; its compiled snapshot is not used.

## Updating

1. Clone or update both repositories next to this one, for example in `../models.dev` and `../model-prices`. The script reads them offline; it does not fetch.
2. Run:

   ```bash
   python3 scripts/update-prices.py import-amendments --model-prices ../model-prices
   python3 scripts/update-prices.py build --models-dev ../models.dev
   python3 -m unittest discover -s scripts/tests
   ```

3. Review the diff of `prices.json`. Each model is on one line, so a price change shows as a changed line.
4. Increase the analysis output version, because cached analyses contain costs from the old table.
5. Commit, naming both source commits. `prices.json` records the models.dev commit in `modelsDev.commit` and the model-prices commit in `amendmentsImportedFrom.commit`.

`build --check` fails if `prices.json` does not match its inputs.

## Amendment format

Each amendment is a `[[amendment]]` table in a file in `amendments/`:

```toml
[[amendment]]
provider = "openai"                  # models.dev provider ID
model = "gpt-5.6-sol"                # models.dev model ID
valid_from = "2026-08-21T00:00:00Z"
valid_until = "2026-08-25T04:37:24Z" # exclusive
input = 4.0                          # US$ per million tokens
output = 20.0
cache_read = 0.4                     # optional
cache_write = 5.0                    # optional
tiers = [{ above = 272000, input = 8.0, output = 30.0, cache_read = 0.8, cache_write = 10.0 }]  # optional
source = "https://openai.com/index/gpt-5-6/"  # required
basis = "documented"                 # "documented" or "firstObserved"
note = "Why this amendment exists."  # optional
```

An amendment without `valid_until` needs one of:

- `replaces = { input = 5.0, output = 30.0 }`: the models.dev rates it corrects. It stops applying as soon as models.dev records different rates, so a later fix or price change in models.dev ends it without an edit here.
- `until_listed = true`: it applies until models.dev first lists the model. This is used for prices read from a provider's page before models.dev added the model.

When several amendments cover the same time, `manual.toml` wins, then model-prices' `corrections.toml`, `research_corrections.toml` and `observed.json`, in that order. An amendment for a model that models.dev does not list adds that model. Amendments apply to one exact provider and model ID; a models.dev alias (a symlinked file) follows its target's prices and amendments until the alias has a price of its own.

## `prices.json`

```jsonc
{
  "schema": 1,
  "modelsDev": { "source": "…", "commit": "…", "committedAt": "…" },
  "amendmentsImportedFrom": { "source": "…", "commit": "…" },
  "billingModes": [ { "provider": "openai-codex", "harness": "pi", "priceProvider": "openai", "billing": "subscription", "source": "…" } ],
  "providers": {
    "github-copilot": {
      "claude-sonnet-4.6": {
        "labEquivalent": "anthropic/claude-sonnet-4-6",
        "prices": [
          { "start": null, "rates": { "input": 0.0, "output": 0.0 }, "commit": "7a163dbc600f" },
          { "start": "2026-06-01T21:10:45Z", "rates": { "input": 3.0, "output": 15.0, "cacheRead": 0.3, "cacheWrite": 3.75 }, "commit": "b3676fd77d0f" }
        ]
      }
    }
  }
}
```

- Each price applies from its `start` until the next one. The first has no start and also applies to earlier calls, because models.dev often adds a model after its launch.
- `rates: null` means models.dev stopped listing a price for the model from that time.
- A price with `commit` comes from that models.dev commit. A price from an amendment has `basis` and `source` instead.
- `labEquivalent` is the lab's own API entry for the model, from models.dev's `base_model`. It is used only for API-equivalent costs of subscription calls.
- Rates are US dollars per million tokens. A tier applies when the whole prompt (uncached input, cache reads and cache writes) exceeds `above` tokens.

## Known limitations

- **Reseller dates.** model-prices only corrects lab APIs. A reseller's price change, such as GitHub Copilot's move to token billing, starts when models.dev recorded it. Copilot's change took effect on 1 June 2026, but models.dev's commit reached main at 21:10 UTC that day, so earlier Copilot calls that day are priced at the old $0 listing. A manual amendment can correct this for a specific model if it matters.
- **Modes.** Only standard rates are kept. No supported harness records whether a call used a fast, flex or priority mode.
- **Coverage.** A model that models.dev never listed with a price, such as OpenCode's `openai/gpt-5.5-fast`, has no entry and its cost stays unknown.

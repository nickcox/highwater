# TokenPlume

TokenPlume is a local Context River visualizer for Pi JSONL and OpenCode SQLite sessions. It reconstructs the active branch and historical model-call context, then lets you follow stable context items through their lifetimes and explicit compaction boundaries.

## Run

```bash
npm --prefix web ci
npm --prefix web run build
cargo run                                  # development and debugging
cargo run --release                        # large-session validation and normal fast use
# Pi-only:
cargo run --release -- --session-root ~/.pi/agent/sessions
# Explicit OpenCode databases (repeatable; may be combined with --session-root):
cargo run --release -- --opencode-db /path/to/opencode.db --opencode-db /path/to/opencode-stable.db
# Optional: --port 43123 --tokenization auto
```

Tokenization is local and offline. `auto` uses the pinned `o200k_base`/`cl100k_base` tokenizers for recognized OpenAI model families, provider serialization estimates where documented, and a versioned Unicode-character heuristic for unknown models. GPT-6-family models on OpenAI/OpenAI Codex (and GitHub Copilot's OpenAI Responses route) provisionally use `o200k_base`: local text-only output counts support this choice, but OpenAI has not published a GPT-6 encoding mapping. Calculated item counts remain estimates, not exact billed prompt tokens. Use `--tokenization strict` to report unsupported profiles without fallback, `heuristic` to force the fallback, or `off` to disable token analysis. Add `--perf-diagnostics` to emit aggregate stage timings and operation counts without session content.

Open the printed localhost URL. The server binds only to `127.0.0.1` and never modifies session files. Returning to a recently viewed session displays its bounded browser-cached analysis immediately, then conditionally revalidates it in the background with the server ETag. A failed refresh leaves the valid cached view in place and shows a warning.

## OpenCode support

Without explicit source flags, discovery includes an existing `~/.pi/agent/sessions` and existing `opencode.db` / `opencode-stable.db` files under `$XDG_DATA_HOME/opencode` (default `~/.local/share/opencode`). Either harness can be absent. An explicit `--session-root` remains Pi-only unless `--opencode-db` is also provided; explicit database paths replace the default database list. Missing explicitly configured sources fail startup. Sources are read locally, never migrated or opened with a writable fallback; no credentials or account tables are queried, and referenced files/URLs are never fetched.

The picker offers **Harness: All harnesses / Pi / OpenCode** and combined title/directory search. Filtering does not switch the open session. Mixed results identify the recording application; an OpenCode child remains a separate session, not merged parent context. Portable `opencode-…` references contain no database path. Duplicate native IDs across databases are ambiguous and rejected rather than selecting an arbitrary copy.

| Area | Current support |
| --- | --- |
| Storage | Legacy `session` / `message` / `part` and modern `session_v2` / `session_message`, including modern-only databases. Modern records use native `seq` order. Mixed databases select one generation per session, never a combined usage ledger. Experimental context/input layouts remain unsupported. |
| Replay | Legacy invocation/results and pruning revisions; modern inline reasoning/tools, usage-only assistants, recorded system updates and injected context. Modern completed compactions replace history with the recorded summary **and serialized recent context**. Failed/running compactions do not reset history; terminal and superseded checkpoints have no invented exposure. Reverts, native encrypted checkpoints, unknown record types, and unaudited legacy tail/synthetic/multi-step histories fail closed. |
| Coverage | A visible **Reconstructed conversation only** notice and structured limitations. Frozen modern system updates are retained, but are not a complete historical baseline. Generation selection, migrated request boundaries, missing compaction usage, and multi-request compaction billing aggregates are explicitly qualified. |
| Usage / cost | Independent optional recorded counters and harness-recorded total cost. Native v2 output excludes reasoning, but migrated counters are copied unchanged; layout/creation version do not establish per-message accounting. Ambiguous output remains unavailable. No Pi cost allocation, inferred API, cache economics, duration, or billed-charge claim. |
| Freshness | Committed SQLite snapshots and per-session content digests before cache hits/304s; DB/WAL/SHM hints plus two-second polling for catalogue invalidation and database replacement. Healthy sources advance while failed sources retain their last-good catalogue. |

For duplicate IDs within one database, a strictly newer legacy session row selects legacy; otherwise a modern projection wins. A missing modern projection falls back to legacy only when timestamps tie and legacy messages exist. A newer empty modern history never resurrects older legacy content. This recency rule is a qualified selection policy, not proof of writer authority. IDs duplicated across different databases remain ambiguous.

SQLite read budgets are 32 MiB per value/row, 256 MiB aggregate loaded strings, 200,000 legacy message-plus-part or modern message rows, and 50,000 discovered sessions; the busy timeout is 250 ms. These are source-read budgets, not total RSS limits. Mixed large-source/oversized-response stress measured roughly 848 MiB sampled server RSS; heavy sessions need substantial memory. Conditional requests still read/hash a current snapshot (about 445 ms for the synthetic ~128 MiB source). Responses above the 16 MiB response-cache budget are regenerated even for conditional requests. A response represents the committed snapshot read by that request; later commits appear on refresh. See [implementation evidence and remaining audits](plans/opencode-analysis-notes.md).

## Context River interactions

Where comparable recorded Input is available, a dashed **Reported input** line and hatched **Unreconciled input** overlay extend the known stack to that value. Both grouping modes and vertical scales include the reference. Missing comparisons break the line; estimates above reported Input are never shrunk. The gap is an approximate difference—not recovered context items—and does not affect item counts, lifetimes, token-turns, Composition or cost attribution. See [design notes](plans/unreconciled-input.md).

- Move across chart space to move the nearest-call crosshair. Click empty chart space or a call label to pin call details; click a ribbon to select a context item. Hover previews are supplementary.
- The toolbar shows the visible call range, equal-sized **‹ / ›** call-selection buttons, zoom controls, **Fit all**, and **Latest**. Stepping preserves the selected item (including when absent at the new pin) and zoom, nudging the target into view only near/outside a viewport edge. Without a pin, the fresh/Fit all overview starts Next at the first call and disables Previous; a zoomed/scrolled view steps from its nearest centre call. Use **← / →** to step calls, or **h / l** while the River workspace has focus. Text entry, composition/IME, modifier shortcuts and tab navigation retain their own keys; Composition does not intercept these call shortcuts. A compact **Go to call** field alongside the zoom controls pins the requested call, preserves the selected item and current zoom (including Fit all), and nudges it into view when needed. Manual range fields are removed; drag an area or use zoom controls instead. Escape in the call field cancels the entry without clearing the pin/item. Escape within View options closes that disclosure and restores summary focus.
- **View options** contains vertical scale and Items/Item types display. River uses one 500px-high layout (the former Balanced layout); older saved Compact settings are ignored without resetting other preferences. The chart's Y-axis shows readable stack-weight ticks and units. **Session scale** is the fresh default and keeps heights comparable across the session; opt-in **Visible calls** uses visible call columns plus interpolated viewport-edge samples, so ribbon heights change as you pan or zoom. Always read the current axis before comparing heights. When token geometry is unavailable, the axis explicitly describes structural placeholder weight rather than tokens.
- Range, pan, and pinch gestures are isolated in a small transition module. Pointer cancellation/lost capture, release outside the plot, window blur, and component teardown clear the gesture without leaving a stale drag or changing selection.
- The session summary keeps model-call count, context-item count, peak calculated context, and **Harness-recorded cost** visible. These amounts were recorded by Pi or OpenCode using configured model rates, not a provider invoice. Recorded zero does not necessarily mean free. Open **Session details** for provider usage, compactions, tokenization coverage, reconciliation, model/provider, and session metadata.
- Call and item panels keep key values and actions visible; usage breakdowns, token diagnostics, profiles, and technical identifiers use native disclosures. Copy buttons provide feedback for IDs.
- On wide screens, the Context River and full-session lifespan list share the main column. A compact, bounded sticky call/item inspector appears alongside them only when an item or call is selected. Content preview, estimate basis, diagnostics and identifiers remain independently available; section choices survive panel remounts within the session. **View details** deliberately reveals and focuses the selected item's summary inside that inspector; with no selection it focuses the inspector prompt. Hover and selection never open or scroll it implicitly.
- **Composition** is a separate tab that starts in **Cumulative** scope, with **At call** available for point-in-time estimates. Cumulative values are estimated token-turns: each present item's applicable estimate is added once per model call through the pinned endpoint, or across the whole session when unpinned. This measures input-context exposure, not unique content, provider usage, billed tokens, or cost. Treemap area and shares use available scoped estimates; missing and partial coverage stays qualified, while zero/unavailable/tiny contributors remain inspectable in the complete ranked **List**. Provider prompt counts, known request framing, and reconciliation details remain separate and are compared only at call scope.
- Lifespan browsing searches source labels and bounded previews (up to 120 characters), filters by item kind, and sorts by token-turn exposure, size, or first appearance. Size uses one shared token-estimate profile with the widest numeric coverage; missing estimates sort last. The call axis and compaction markers describe the full session independently of chart zoom. With no filters, the disclosure shows one total item count; filtered results show the available/total count. Click/tap a position on a lifespan segment to select its item and pin the nearest real call within that segment. Item-label clicks and keyboard Enter/Space select only the item, preserving the pin; items without call presence, including terminal summaries, remain selectable without inventing a call. These actions do not switch views or automatically pan/zoom River.
- **Copy view link** shares navigation through an unversioned v1 URL fragment: a compact session reference such as `pi-a83f9c2d71b4` (harness plus a hash of its native session ID), River/Composition view, River grouping (`display=items` / `display=itemTypes`, saved preference when omitted, with **Items** as the fresh default), Composition scope, approximate visible call range, pinned call and selected item. Reload and Back/Forward restore valid references; stale/inaccessible references produce feedback rather than fabricated selections. Ambiguous session references are rejected rather than selecting an arbitrary file. Pan/zoom updates replace the current history entry, while explicit navigation can add entries. Links carry opaque identifiers, not session content or local paths, and do not grant access or distribute the session. Other presentation settings stay local. Explicit URL grouping overrides stored grouping; missing or invalid values use the saved preference (or Items if none). Restoring links does not write preferences. Clipboard-denied browsers get a selectable manual-copy field; copied links omit URL credentials and unused query parameters. See [delivery notes](plans/shareable-view-links-notes.md).
- **Item types** uses a fixed semantic palette shared by grouped bands and their legend: User Message blue, Tool Result gold, Assistant Message teal, Compaction Summary lavender, with distinct colours for the other categories. These colours identify types, not cache status; individual-item colours and Composition remain ID-hashed and unchanged. Clicking or keyboard-activating a grouped band opens a viewport-bounded breakdown near that band, without scrolling the page; Escape/Close returns focus without scrolling. Moving the page or chart dismisses the breakdown, while its member list can scroll independently.
- **Selected item** identifies and outlines only the exact ribbon. Compaction lineage remains available through direct connectors, item details, and lineage actions; sibling sources are not treated as one visual selection group, and other ribbons stay at normal opacity.
- Press `Escape` to close an active disclosure/overlay first, including expanded **Cache & cost** (focus returns to its trigger). Subsequent presses clear the selected item, then the pin, then restore Fit all. **Clear selected item and pinned call** clears both at once.

The borderless **▸ Cache & cost / ▾ Cache & cost** disclosure starts collapsed for fresh preferences. Expand it for **Cache / Cost / Off** and **Tokens / Share (%)**; collapse/Off retains the last mode and cache view. Explicit River/economics preferences are remembered across sessions and reloads in one bounded, versioned localStorage entry (enums/booleans only; no session identities, content, selection or navigation). Choose **Session scale** and **Items** directly to restore the River defaults; there is no blanket Reset action. Blocked storage leaves the in-memory UI usable.

The **Cache / Cost / Off** track reports only policy-supported, provider-usage-derived cache buckets and source-qualified per-call cost totals. Cache ratios and cost are not assigned to individual items; unsupported, missing, partial, and measured-zero data remain distinct. The mode controls and compact legend sit beside the economics plot; its exact readout is a normal-flow chart footer that remains aligned while the River pans. The track keeps quantitative marks on the shared call axis and places compaction, target-change, and cache-share observations in a bounded event lane with explicit event counts, keyboard/touch details, and exact call mappings. Ribbon thickness and Composition use local item token estimates, not provider prompt totals. Genuinely unavailable token geometry is shown explicitly rather than replaced with serialized-byte weights. The legacy `displayWeight` field remains a serialized-byte diagnostic, never a token-geometry fallback. Image previews identify encoded source-data size (usually base64), not decoded image bytes. In individual-item River view, subdued colour-blended flows join summarized source bands to the summary's actual band; retained items continue unchanged. These overlapping flows show structural, lossy replacement—not conserved tokens or per-source contributions to the summary. Hovering/selecting a source emphasizes its connection; selecting the summary gently emphasizes its incoming flows. Grouped Item types view does not invent individual merge mappings, and terminal summaries without drawable call geometry do not acquire fabricated bands. These economics mappings are audited against Pi v0.78.0 adapters and should not be read as universal provider semantics.

## Development checks

Use Rust **1.88 or newer**, Node **24 LTS or newer**, npm, Bash, Python 3, and curl. The Rust minimum is declared in `Cargo.toml` and tested with 1.88.0: the locked dependency graph includes `ruzstd` requiring 1.87, and pinned `tiktoken` 4.1.2 uses let-chains requiring 1.88. Dependency changes must preserve this floor or explicitly advance and test it; the edition alone does not establish compatibility.

```bash
scripts/check.sh          # locked installs, Rust/frontend checks, live contract, embedded release build
scripts/check.sh --full   # also Chromium, mocked + debug/release integrated browser checks, large benchmark

# Optional focused checks:
scripts/check-contract.sh
rustup toolchain install 1.88.0 --profile minimal --component rustfmt --component clippy
RUSTUP_TOOLCHAIN=1.88.0 scripts/check.sh
```

`check-contract.sh` runs a test-only Rust producer using the production parser/analyzer/serializer, then passes 92 fresh checked-in/synthetic outputs to the production TypeScript `indexAnalysis` validator. Cases cover all tokenization policies, opaque profile identities, exposure/economics coverage, terminal summaries, per-call timing/provenance, safe-number boundaries, and aggregate exhaustion. Controlled estimates use the same production derivation stages without giant test payloads; invalid source/normalized inputs must fail in Rust before export. The temporary export directory is always removed, and the contract suite fails rather than silently skipping when exports are missing. Its standalone Vitest config keeps normal frontend tests independent of generated files.

`.github/workflows/check.yml` defines Rust 1.88/stable checks and full Node 24 contract/browser validation on GitHub Actions. Local checks are independently reproducible; a newly added workflow is not evidence that a remote CI run has completed.

Frontend formatting is configured in `web/.prettierrc.json` for Svelte and TypeScript source, tests, and root TypeScript configs; generated `web/dist/` assets are excluded. Run `npm --prefix web run format` to apply it and `npm --prefix web run format:check` to verify it.

The browser smoke suite uses Playwright/Chromium and deterministic mocked API responses. Install its browser once with `npm --prefix web run test:browser:install`. `scripts/browser-smoke-integrated.sh` builds and checks the Rust-served embedded frontend against a generated sanitized session; it uses the debug binary by default, or the release binary when `TOKENPLUME_BROWSER_BUILD_PROFILE=release` is set. The integrated path also exercises the generated session's cache track and pinned-call Composition. `scripts/browser-smoke-opencode-integrated.sh` generates an isolated SQLite database plus Pi session and checks mixed discovery, filtering, OpenCode coverage/cost labels, links, Composition, WAL refresh, and narrow layout; it supports the same debug/release switch. To save desktop and narrow baseline screenshots outside the repository, set `TOKENPLUME_BASELINE_SCREENSHOTS=/tmp/tokenplume-browser-baseline` when running `npm --prefix web run test:browser`.

Build the frontend before Rust so `rust-embed` packages the current `web/dist/` assets into the executable. The generated `web/dist/` assets are tracked so a clean checkout can build the embedded binary without requiring Node at runtime; refresh and commit them whenever the frontend changes.

For OpenCode HTTP/WAL/RSS validation, run `python3 scripts/benchmark-opencode.py --full` after a release build. It creates only synthetic SQLite data, checks conditional freshness, oversized uncached responses, checkpoints, concurrent reads and 200 WAL commits, and removes its temporary database. Optional real-source browser acceptance is `node scripts/accept-opencode-readonly.mjs /path/to/opencode.db`: it opens the database through the read-only server and checks a representative qualified session without screenshots, traces, transcript dumps, or database writes.

For generated performance validation, run `scripts/benchmark-context-river.sh large`. It uses only deterministic generated text, reports median cold/warm requests, response bytes, and observed peak RSS, then removes its temporary session root.

## Architecture

- Rust owns source-adapter parsing, branch/context reconstruction, offline tokenization, reconciliation, derived metrics, and the Axum API.
- Pi graph validation and typed interpretation precede stable-index reconstruction and finalization. Normalized references, presence, and raw safe integers are validated before a borrowed preparation stage plans unique item/profile estimates; call/item derivation and DTO assembly reuse that plan.
- Catalogue scheduling owns debounce/retry/rate/shutdown decisions independently of discovery. One analysis service owns the four-entry/16-MiB response cache and active flights under one short lock, with at most two blocking analysis jobs. Flights register before permit acquisition and survive request cancellation; typed shared failures map centrally, and best-effort category reporting cannot strand a completed flight. These are response-cache/concurrency limits, not total process-memory bounds.
- Source-neutral normalized domain types keep provider usage/costs, calculated estimates, and missing-value semantics distinct.
- TypeScript validates and indexes the normalized analysis response; it does not tokenize or infer missing payloads.
- D3 computes scales, SVG ribbon paths, and the Composition treemap layout.
- Svelte owns rendering and interaction state.

The primary endpoint is `GET /api/sessions/{id}/analysis`, where `id` is the portable `pi-…` / `opencode-…` reference returned by `GET /api/sessions`. Legacy Pi canonical-path lookup remains constrained to discovered files; OpenCode database paths/native IDs are not accepted from HTTP. It contains labels, structural metadata, bounded reader-facing content previews, and normalized economics, but it does not duplicate full raw JSONL records or provider payloads. `ContextItem.label` is a bounded source-aware title/accessibility label; Pi tool results use their matching selected-branch invocation when available: **Assistant · write** labels the request, while **Write result · filename** labels the returned result (likewise Read, Edit, Bash, Grep and Find). Previews remain separate content and are never reinterpreted as arguments. Top-level `schemaVersion` is the sole public envelope-version marker; the current response schema is version 11. Failed/aborted Pi attempts with explicit default-zero counters expose those values in `usage.placeholder`, not as measured usage or cost. Qualified counters are unavailable, totals retain missingness, and the reported-input reference breaks at these attempts. Shared call inspectors show **Recorded output** (`usage.recordedOutput`) and **Recorded reasoning** (`usage.reasoning`, when present) as separate source counters. `usage.outputReasoningRelationship` describes their overlap; accounting details stay in the usage disclosure, not a headline warning. The existing `usage.output` / `reportedCompletionTokens` remain normalized completion totals (including reasoning exactly once when known), and are not replaced by raw counters for costs, cumulative totals, or throughput. Missing counters are not inferred from reasoning text or treated as zero. OpenCode responses include `reconstruction: {status: "partial", explanationCodes: [...]}`; Pi omits this optional field. Responses include an ETag and support `If-None-Match` with an empty-body `304 Not Modified` response.

Each `modelCalls[].timing` preserves `startedAtMs` (Pi assistant-message initialization) and `recordedAtMs` (session-entry persistence) as nullable UTC epoch milliseconds. Valid instants are retained independently, even for unknown/custom APIs. For checked Pi built-in APIs, a positive same-response interval yields `durationMs` with basis `pi-message-timestamps`; this is approximate client-observed elapsed time, including waiting, retries and possible extension processing—not generation-only time or subsequent tool execution. Successful terminal responses with reported output yield `effectiveOutputTokensPerSecond = output × 1000 / durationMs`; output already includes reasoning, which is not added twice. Failed/aborted response rates, missing output, absent/reversed/zero intervals, and unverified API timing semantics remain unavailable. Malformed optional timestamps become null without discarding otherwise usable sessions. No inter-message gaps, TTFT or live-stream timing are inferred. The Model call panel exposes qualified elapsed time and effective output rate; absolute instants are captured for future use, not displayed yet.

Raw public analysis integers are limited to `Number.MAX_SAFE_INTEGER`; invalid required/count source/normalized values are rejected before successful serialization. Derived range exhaustion remains qualified `null`, never a recovered total or misleading subtotal. Exposure coverage distinguishes an observed numeric zero, partial available observations, and unavailable values; terminal summaries are structural/selectable but have no fabricated exposure. Known request framing is a text-only approximation for supported chat routes, not universal provider serialization or billing.

Internal output/cache identity is **16**, tokenization profile identity is **v4** (opaque, delimiter-safe IDs preserving absent versus literal target values), and payload fingerprint encoding is **4**. These are not additional public envelope-version fields. Pi source verification retains size/mtime identity: rewrites preserving both can escape detection, and filesystem races are not completely eliminated. OpenCode cache identity uses the configured database, native session ID, and content digest from a committed read transaction instead of file mtime/size. Shutdown drain timeouts acknowledge that blocking work may remain; detached scan results cannot publish after shutdown.

The completed implementation and validation evidence are recorded in [backend maintainability notes](plans/backend-maintainability-notes.md), following the [milestone plan](plans/backend-maintainability-implementation-plan.md). Persistence and incremental analysis remain deferred rather than being implied by these changes.

Recorded Pi system instructions and tool declarations are replayed into immutable per-call context revisions, including ordered section patches, tool changes and compaction checkpoints. They appear in River and Composition without being charged twice or included as summary-source lineage. Cumulative Composition accounts for each revision's actual item-call appearances; it does not add old and new revisions to the same call. Older logs can lack this material: absence is not evidence of zero tokens. Provider-reported usage and cost remain independent of these local estimates.

System/tool estimates describe logical replayed context, not exact provider wire framing; generic declaration JSON and provider-specific mid-conversation updates can differ from the transmitted request. These estimates therefore report partial coverage. Pi 1.0.4's docs describe `replace: true`, but its installed replay helpers ignore it; TokenPlume marks affected histories unavailable rather than guessing a reset, until a complete compaction checkpoint restores a known baseline. An authoritative recorded modern loadout supersedes legacy standalone declaration records. No historical prompt is inferred from current installation files or provider residuals.

GitHub Copilot's `openai-responses` route has a dedicated three-bucket cache policy: prompt tokens are normalized uncached input + cache read + cache write. Missing buckets remain incomplete, not zero; complete zero prompts have no ratios. Pi's configured-rate cost components can be interpreted when all are recorded, but are **not Copilot subscription charges, premium-request counts or invoices**. Direct OpenAI policies remain conservative about older adapter-dropped writes and reject unexpected positive write buckets; model names alone never grant policy support.

`GET /api/sessions` returns the current catalogue with generation, revision, availability, and ETag headers. `GET /api/events` provides content-free SSE invalidation hints; browsers refetch the catalogue rather than treating SSE as an event log. Live discovery is local and remains usable through ordinary HTTP when SSE or filesystem watching is unavailable. If filesystem watching cannot be initialized for an existing readable root, the server starts in degraded mode and performs bounded request-driven catalogue refreshes. OpenCode also polls every two seconds, including after watched-directory replacement. Transient source failures recover after a successful scan without disabling healthy watchers; actual watcher loss remains marked degraded until restart, with polling/request-driven updates still available.
